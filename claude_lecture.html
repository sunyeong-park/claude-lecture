💡 AI · LLM · AI 에이전트 — 차이점

AI(인공지능)는 컴퓨터가 사람처럼 판단하는 기술 전체입니다.
LLM(대형언어모델)은 방대한 텍스트를 학습해 대화하는 AI입니다. 클로드가 여기에 해당합니다.
AI 에이전트는 단순 답변을 넘어 파일 생성·앱 연동·작업 자동화를 직접 실행하는 AI입니다.

Free vs Pro 차이

Free: 메시지 횟수 제한, 기능 일부 제한
Pro: 넉넉한 메시지 한도, 최신 모델(Opus), Projects · 파일 업로드 · MCP 풀 지원

Pro 플랜 요금 (2025 기준)

월 $20 (약 2만 7천원)

claude.ai → 설정 → Upgrade to Pro

  3. "이 앱이 기기를 변경하도록 허용하시겠습니까?" → 예 클릭
  4. 설치 완료 후 자동 실행 → Claude.ai Pro 계정으로 로그인

개념이 무엇인지 한 번만 이해해두면 됩니다. 작업 중 모르는 용어가 나오면 클로드에게 "이게 뭐야?"라고 바로 물어보세요.

AI · 클로드 기본 용어
토큰 (Token)

AI가 처리하는 텍스트 단위. 한글 1글자 ≈ 1~2토큰. 대화가 길수록 소모 증가. Pro는 한도 넉넉.

모델 (Model)

AI의 두뇌 버전. Claude Sonnet(빠름) ↔ Claude Opus(정확함). 작업에 따라 선택 가능.

패키지 / npm

누군가 만들어둔 기능 묶음. npm은 그 패키지를 설치하는 앱스토어. npm install로 설치.

CLI

마우스 없이 타이핑으로 명령하는 방식. Windows에서는 PowerShell 또는 명령 프롬프트(cmd).

경로 (Path)

파일·폴더의 주소. C:\Users\이름\Desktop처럼 위치를 표시. Windows는 대소문자 구분 없음.

데이터·인프라 기본 용어 — 비유로 이해하기
💡 도로 비유로 한번에 이해하기

데이터가 이동하는 과정을 도로·창고·경비원으로 비유하면 전체 구조가 한눈에 보입니다. 아래 카드를 순서대로 읽어보세요.

🏭 데이터베이스 (DB) = 창고

데이터를 체계적으로 쌓아두는 창고. 중·대규모 작업에서 파일 대신 사용. 엑셀보다 훨씬 많은 데이터를 빠르게 처리.

☁️ 클라우드 (Cloud) = 남의 창고

남의 데이터센터를 빌려 쓰는 것. 내 컴퓨터 대신 AWS·GCP·Azure 서버를 빌려 24시간 프로그램 운영. 끄지 않아도 계속 작동.

🛣️ 서버 (Server) = 도로

데이터가 이동하는 통로(도로). 요청을 받아 처리하고 결과를 돌려주는 컴퓨터. 디스코드 봇·웹사이트·API 모두 서버 위에서 실행.

🚦 API = 목적지별 전용 도로

앱과 앱이 대화하는 전용 도로 + 도로 규칙. API 권한=진입 조건, API 키=통행증. "클로드 API"는 내 프로그램에서 클로드를 가져다 쓰는 연결 창구.

💂 RLS = 경비원

데이터베이스의 경비원(도로 규칙). 누가 어떤 데이터를 볼 수 있는지 행(Row) 단위로 통제. "A유저는 자기 데이터만, B유저는 전체 조회 가능"처럼 세밀하게 설정.

🗣️ SQL = DB에 말 거는 언어

데이터베이스에 말을 거는 언어. "3월 매출 가져와", "신규 회원 목록 보여줘"처럼 DB에 질문하거나 명령할 때 사용. 클로드가 대신 짜줄 수 있음.

⚡ 인덱스 (Index) = 도로 속도 최적화

데이터베이스 도로 속도 최적화. 자주 검색하는 컬럼에 인덱스를 걸면 수백만 건 중에서도 빠르게 찾음. 책의 색인(목차)과 같은 원리.

Node.js CLI 설치 & Claude Code 실행

2시간 · 설치 70분 + 오류 대응 30분 + 실습 20분 · 관리자 PowerShell 필수
학습 목표
  • Node.js를 CLI(PowerShell)로 직접 설치하고 설치 확인하는 법
  • npm으로 Claude Code 설치 및 경로 확인
  • Claude Code 실행 전 파일 경로 확인 루틴 습득
  • 기본 슬래시 명령어 (/help, /clear, /status) 사용
💡 Node.js란?

JavaScript를 브라우저 밖(내 컴퓨터)에서 직접 실행할 수 있게 해주는 프로그램입니다. Claude Code는 Node.js 위에서 실행되기 때문에 먼저 설치해야 합니다. npm(패키지 설치 도구)은 Node.js 설치 시 자동으로 함께 설치됩니다.

STEP 1 — Node.js CLI 설치 (winget 사용)
💡 왜 CLI로 설치하나요? — 웹사이트에서 직접 내려받아도 되지만, CLI 설치에 익숙해지면 버전 관리·재설치·업데이트를 훨씬 빠르게 할 수 있습니다.
STEP 1-1 · winget으로 Node.js LTS 설치
# winget은 Windows 10/11 기본 내장 패키지 관리자 # 관리자 PowerShell에서 실행 winget install OpenJS.NodeJS.LTS # 동의 메시지가 뜨면 Y 입력 후 Enter # 설치 완료 후 반드시 PowerShell을 닫고 다시 열기!
STEP 1-2 · 설치 확인 — 숫자가 나오면 성공
# Node.js 버전 확인 node --version # 정상 출력 예시: v20.11.1 # npm 버전 확인 npm --version # 정상 출력 예시: 10.2.4 # 설치 경로 확인 where node # 정상 출력 예시: C:\Program Files\nodejs\node.exe
💡 npm이 설치되지 않은 경우란?

보통 Node.js를 설치하면 npm이 함께 설치됩니다. 하지만 아래 상황에서는 npm만 따로 없거나 깨진 경우가 있습니다.
① Node.js가 오래전에 수동 설치된 경우  ② 회사 PC 정책으로 일부만 설치된 경우  ③ npm이 PATH에는 없지만 파일은 있는 경우
이럴 때 아래 방법으로 CLI에서 직접 npm을 설치·복구할 수 있습니다.

STEP 1-3 · npm이 없거나 깨진 경우 — CLI에서 직접 설치
방법 1 — npm 자체 설치 스크립트 (가장 간단)
# npm 공식 설치 스크립트 (관리자 PowerShell) winget install OpenJS.NodeJS.LTS --force # --force 옵션으로 기존 설치를 덮어쓰기 # 설치 완료 후 PowerShell 닫고 다시 열기! # npm만 따로 최신 버전으로 업그레이드 npm install -g npm@latest
방법 2 — Node.js 완전 제거 후 재설치
# 기존 Node.js 완전 제거 winget uninstall OpenJS.NodeJS winget uninstall OpenJS.NodeJS.LTS # 남은 npm 캐시·설정 폴더 정리 Remove-Item -Recurse -Force "$env:APPDATA\npm" -ErrorAction SilentlyContinue Remove-Item -Recurse -Force "$env:APPDATA\npm-cache" -ErrorAction SilentlyContinue # Node.js LTS 새로 설치 winget install OpenJS.NodeJS.LTS # PowerShell 닫고 다시 열기 → 확인 node --version npm --version
방법 3 — npm PATH 수동 등록 (파일은 있지만 명령어가 안 될 때)
# npm 파일이 실제로 있는지 확인 Test-Path "C:\Program Files\nodejs\npm.cmd" # True가 출력되면 파일은 있고 PATH만 없는 것 # 현재 세션에서 즉시 PATH 추가 (임시) $env:PATH += ";C:\Program Files\nodejs" # 확인 npm --version # 영구 등록: 시작 → 시스템 속성 → 고급 → 환경변수 # → 시스템 변수 → Path → 편집 → 새로 만들기 # → C:\Program Files\nodejs 입력 → 확인
💡 어떤 방법을 써야 하나요?
방법 1 — npm 명령어 자체가 없거나 오래된 버전일 때 (가장 먼저 시도)
방법 2 — node·npm 둘 다 이상하게 동작할 때 (처음부터 새로 깔기)
방법 3 — node --version은 되는데 npm --version만 안 될 때 (PATH 문제)
⚠️ Node.js 설치 오류 해결법
'winget'은(는) 인식되지 않습니다
원인: Windows 구버전 (winget은 Windows 10 1709 이상 필요)
해결: 아래 Chocolatey 방법으로 설치
대안 — Chocolatey로 설치
# Chocolatey 설치 (관리자 PowerShell) Set-ExecutionPolicy Bypass -Scope Process -Force; ` [System.Net.ServicePointManager]::SecurityProtocol = ` [System.Net.ServicePointManager]::SecurityProtocol -bor 3072; ` iex ((New-Object System.Net.WebClient).DownloadString('https://community.chocolatey.org/install.ps1')) # Chocolatey로 Node.js LTS 설치 choco install nodejs-lts -y
'node'은(는) 내부 또는 외부 명령... 아닙니다
해결 1: PowerShell 완전히 닫고 다시 열기
해결 2 (그래도 안 되면): 컴퓨터 재시작 후 재시도
npm WARN (노란색) / npm ERR! (빨간색)
WARN(노란색) → 경고일 뿐, 무시해도 됩니다
ERR!(빨간색) → 실제 오류, 메시지 전체를 강사에게 보여주세요
STEP 2 — Claude Code 설치 & 확인
Claude Code 설치 및 경로 확인

🗂️ Git · GitHub — 차이점

Git은 내 컴퓨터에서 파일 변경 이력을 관리하는 도구입니다. "저장 버튼"의 업그레이드 버전 — 언제 무엇을 바꿨는지 전부 기록하고, 이전 상태로 되돌릴 수 있습니다.

GitHub는 Git으로 관리한 코드를 인터넷(클라우드)에 올려두는 저장소입니다. 팀원과 공유하거나 어디서든 내려받을 수 있습니다.

비유: Git = 내 컴퓨터의 자동저장 이력 / GitHub = 그 이력을 올려두는 구글 드라이브

Git (로컬)

내 컴퓨터에서 버전 관리. 변경 이력 저장, 이전 상태 복구, 브랜치로 분기 작업.

GitHub (원격)

인터넷 저장소. 팀 협업, 코드 공유, 어디서든 접근. 세계 최대 코드 플랫폼.

Repository (저장소)

프로젝트 단위 폴더. 코드·파일·변경 이력을 모두 담는 하나의 프로젝트 공간.

STEP 3-1 — 간단한 페이지 만들고 GitHub Pages로 배포하기
💡 GitHub Pages란?

GitHub 저장소에 올린 HTML 파일을 무료로 웹사이트처럼 공개할 수 있는 기능입니다. 별도 서버 없이 내아이디.github.io/저장소이름 주소로 바로 접근할 수 있습니다.

실습 흐름: ① 파일 생성 + push (클로드가 자동) → ② Pages 활성화 (브라우저에서 최초 1회만) → ③ 이후 수정은 클로드에게 요청하면 자동 배포

① 파일 만들기 + 올리기

Claude Code에게 요청. 파일 생성 + add·commit·push 자동 실행.

② Pages 활성화 (1회만)

브라우저에서 저장소 Settings → Pages 켜기. 딱 한 번만 하면 됨.

③ 이후 수정 = 자동 배포

클로드에게 수정 요청 + "GitHub에 올려줘" → push되면 1~2분 후 자동 반영.

1단계 — Claude Code로 파일 만들고 GitHub에 올리기
# Claude Code 실행 후 아래 입력 간단한 자기소개 웹페이지를 만들어줘. 파일명은 index.html로 저장해줘. 조건: - 이름: [내 이름] - 한 줄 소개: [자유롭게] - 배경색은 흰색, 글씨는 깔끔하게 - 모바일에서도 잘 보이게 # 파일 만들어지면 바로 이어서 입력 방금 만든 index.html 파일을 GitHub에 올려줘. 커밋 메시지는 "첫 페이지 추가"로 해줘.
2단계 — GitHub Pages 활성화 (브라우저에서 딱 한 번만)
# 브라우저에서 내 GitHub 저장소 접속 후 # Settings 탭 → 왼쪽 메뉴 "Pages" 클릭 # → Source: "Deploy from a branch" 선택 # → Branch: main / (root) 선택 → Save 클릭 # 1~2분 후 아래 URL로 접속 가능 # https://내아이디.github.io/저장소이름/
💡 이후 수정은 자동 배포 — Pages를 한 번 켜두면, 이후에는 Claude Code에서 수정 후 push만 하면 1~2분 안에 자동으로 배포됩니다. 브라우저 설정을 다시 건드릴 필요 없어요.

Git이 설치되어 있고 저장소에 연결만 되어 있으면, 클로드에게 "수정하고 GitHub에 올려줘" 한 마디로 끝납니다.
3단계 — 이후 수정 요청 예시 (자동 배포)
# Claude Code에서 바로 요청 페이지 배경색을 파란색으로 바꿔줘. 바꾸고 GitHub에도 올려줘. 커밋 메시지는 "배경색 변경"으로. # 클로드가 파일 수정 + add + commit + push 자동 실행 # → 1~2분 후 사이트에 자동 반영
⚠️ GitHub Pages 자주 나오는 오류 해결법
Pages URL 접속 시 404 Not Found
원인 1: 파일명이 index.html이 아닌 경우 → 파일명 정확히 확인
원인 2: Pages 활성화 후 아직 배포 중 → 2~3분 기다린 후 새로고침
원인 3: Branch가 main이 아닌 master인 경우 → Settings → Pages에서 브랜치 재확인
Pages 메뉴가 보이지 않음
원인: 저장소가 Private으로 설정됨
해결: 저장소 Settings → General → Danger Zone → "Change repository visibility" → Public으로 변경
push 후 변경사항이 반영 안 됨
해결: GitHub 저장소 → Actions 탭에서 배포 진행 상태 확인. 주황색(진행 중) → 초록색(완료) 되면 새로고침
실습 체크

브라우저에서 내아이디.github.io/저장소이름 URL로 접속해서 내 페이지가 뜨면 성공입니다. URL을 복사해서 카카오톡으로 친구에게 보내보세요!

STEP 4 — CLAUDE.md 개념 & 작성법
💡 CLAUDE.md란?

Claude Code가 프로젝트 폴더에서 실행될 때 자동으로 읽는 지시 파일입니다. 프로젝트마다 다른 규칙을 적용하고 싶을 때 씁니다.

예를 들어, "이 프로젝트는 항상 한국어로 답하고, 파일은 절대 삭제하지 말고, 주석은 영어로 달아라"와 같은 규칙을 저장해두면 매번 설명하지 않아도 됩니다.

CLAUDE.md 없을 때

Claude Code 실행할 때마다 "이 프로젝트 규칙은..." 반복 설명 필요

CLAUDE.md 있을 때

폴더 안에 파일만 있으면 자동으로 읽고 규칙 적용. 설명 불필요.

# 작업 폴더로 이동 cd C:\Users\$env:USERNAME\Desktop\claude-work # CLAUDE.md 파일 생성 New-Item -Name "CLAUDE.md" -ItemType File # 메모장으로 열어서 내용 작성 notepad CLAUDE.md
CLAUDE.md 내용 예시 — 복사해서 붙여넣기
# 프로젝트 규칙 ## 기본 설정 - 모든 답변과 주석은 한국어로 작성 - 파일 삭제는 절대 하지 말 것 (이동만 허용) - 작업 전 반드시 현재 폴더 구조를 먼저 파악할 것 ## 코딩 규칙 - 파일명은 소문자와 하이픈 사용 (예: my-file.js) - 함수마다 한 줄 설명 주석 필수 - 에러 처리 항상 포함 ## 이 프로젝트 설명 - 목적: [프로젝트 목적 입력] - 주요 파일: [주요 파일 목록] - 사용 중인 서비스: [API, DB 등]
💡 CLAUDE.md vs Project Instructions 차이
Project Instructions = Claude.ai·Desktop 채팅 프로젝트 설정 (웹 UI 기반)
CLAUDE.md = Claude Code(터미널)에서 자동으로 읽는 파일 (폴더 기반)
터미널 작업에는 CLAUDE.md, 채팅 작업에는 Project Instructions를 씁니다.

작업 폴더에 CLAUDE.md를 만들고 위 예시 내용을 붙여넣은 후, claude를 실행해서 "지금 프로젝트 규칙 읽어줘"라고 입력해보세요.

🔌 MCP(Model Context Protocol)란?

클로드가 외부 서비스(Notion, Gmail, Slack, GitHub 등)를 직접 사용할 수 있게 해주는 연결 규격입니다.

비유: 클로드는 원래 "두뇌"만 있는 AI입니다. MCP를 연결하면 Notion을 쓰는 손, 메일을 보내는 손, 파일을 여는 눈이 생깁니다.

설정 후에는 "노션에 회의록 페이지 만들어줘"라고 하면 클로드가 직접 Notion을 열고 페이지를 만듭니다.

MCP 없을 때

클로드가 텍스트로 답변 → 내가 직접 Notion/Gmail 열고 복붙

MCP 있을 때

클로드가 직접 Notion 페이지 생성, 메일 발송, 파일 저장까지 자동 실행

연결 가능한 서비스

Notion, Gmail, Google Calendar, Slack, GitHub, Jira, Figma 등 100개 이상

💡 MCP 작동 방식 3단계

① 설정 — Claude Desktop 설정 파일에 MCP 서버 정보 입력
② 인증 — 각 서비스의 API 토큰 발급 후 연결
③ 실행 — 클로드에게 자연어로 요청하면 MCP가 해당 서비스를 직접 실행

🧠 Skills(스킬스)란?

자주 반복하는 지시나 작업 방식을 파일(.md)로 저장해두는 것입니다. 클로드가 특정 작업을 할 때 이 파일을 참고해서 항상 같은 방식으로 처리합니다.

비유: 요리사의 레시피 카드. 매번 재료와 순서를 외우는 대신, 레시피 카드를 보면 항상 같은 맛을 낼 수 있습니다.

"보고서 작성 스킬"을 만들어두면 "보고서 스킬 써서 작성해줘" 한 마디로 항상 동일한 품질의 문서를 만들어냅니다.

Skills 없을 때

매번 "A4 2장, 문어체, 소제목 포함, 표 형식으로..." 라고 긴 지시를 반복 입력

Skills 있을 때

"보고서 스킬 적용해서 작성해줘" 한 마디로 동일한 품질 자동 생성

💡 MCP vs Skills 핵심 차이
MCP = 외부 서비스 연결 (Notion, Gmail 등을 실제로 열고 실행)
Skills = 작업 방식 저장 (클로드가 어떻게 일할지 정해두는 레시피)
둘은 함께 쓰면 더 강력합니다.
Skills 파일 예시 — report-skill.md
# 파일명: report-skill.md # 저장 위치: C:\Users\[이름]\Desktop\claude-work\skills\ ## 보고서 작성 규칙 ### 형식 - 문어체 (합니다/입니다 체) - 제목: # 기호 / 소제목: ## 기호 - 데이터 필요 시 [데이터 필요] 표시 - 표 가능한 부분은 마크다운 표로 작성 - A4 2장 분량 유지 ### 구조 1. 배경 및 목적 2. 현황 분석 3. 제안 사항 4. 기대 효과 5. 결론
Skills 파일 참조해서 요청하기
skills 폴더의 report-skill.md 파일을 읽고 그 규칙에 따라 "재택근무 도입 방안" 보고서를 작성해줘.
서브 에이전트 개념 & 실습
🤖 서브 에이전트(Sub-agent)란?

하나의 클로드가 혼자 모든 걸 하는 게 아니라, 역할을 나눠 여러 클로드가 협업하는 구조입니다.

비유: 혼자 일하는 직원(일반 클로드) vs 팀장 + 팀원들이 역할 분담해서 일하는 팀(서브 에이전트)

예를 들어 "보고서 작성" 작업을 하면, 팀장 에이전트가 전체를 지휘하고 → 조사 담당이 자료를 모으고 → 작성 담당이 글을 쓰는 방식으로 나눌 수 있습니다.

일반 클로드 (혼자)

순차적으로 모든 작업 처리. 단순 작업엔 충분하지만 복잡한 작업은 품질 저하, 속도 느림.

서브 에이전트 (팀)

역할 분담 + 병렬 작업 가능. 리서처가 조사하는 동안 라이터가 다른 섹션 동시 작성 → 더 빠르고 품질 높음.

💡 서브 에이전트의 핵심 장점 — 병렬 작업

일반 클로드는 "조사 → 작성 → 검토"를 순서대로 처리합니다.
서브 에이전트는 리서처·라이터·팀장이 동시에 각자 역할을 수행할 수 있습니다.
예: 리서처가 3개 섹션을 병렬로 조사하는 동안 라이터는 이미 완료된 섹션부터 바로 작성 시작 → 전체 작업 시간 대폭 단축

🔄 서브 에이전트 vs Teams 기능 — 언제 뭘 쓰나?

두 가지는 방향이 반대입니다. 상황에 맞게 골라 쓰세요.

🔽 서브 에이전트 — 탑다운(Top-down)

팀장이 지시 → 팀원이 실행

명확한 목표가 있을 때. 팀장이 전체를 컨트롤하고 팀원에게 역할을 분배.

예: "보고서 써줘" → 팀장이 리서처·라이터에게 각각 지시 → 결과 취합 후 검수

🔼 Teams 기능 — 바텀업(Bottom-up) / 커뮤니케이션

에이전트끼리 자유롭게 소통

아이디어 발산, 토론, 브레인스토밍에 적합. 특정 지시 없이 에이전트들이 자율적으로 대화하며 결론 도출.

예: 리서처·라이터가 커피챗 → 서로 아이디어 교환 → 더 좋은 방향 자율 합의

💡 언제 뭘 쓸까?
명확한 결과물이 필요할 때 → 서브 에이전트 (탑다운)
아이디어가 필요하거나 열린 토론이 필요할 때 → Teams (바텀업)
실제로는 서브 에이전트로 먼저 만들고 → Teams로 옮겨서 소통시키는 방식을 함께 씁니다.
STEP 1 — 서브 에이전트 3개 만들기 (팀장 포함)
Claude Code에서 서브 에이전트 3개 생성 요청
# 팀장 포함 3개의 서브 에이전트 만들어달라고 요청 세 개의 서브 에이전트를 만들어줘. 에이전트 1 — 이름: 팀장 - 역할: 전체 작업을 지휘하고, 리서처·라이터 결과물을 취합 및 검수 - 품질 기준 미달 시 해당 에이전트에게 재작업 오더를 내림 - 말투: 명확하고 구체적인 피드백 제공 에이전트 2 — 이름: 리서처 - 역할: 팀장이 지시한 주제에 대해 핵심 정보를 3가지로 정리 - 말투: 간결하고 객관적으로 에이전트 3 — 이름: 라이터 - 역할: 리서처가 정리한 내용을 받아서 읽기 좋은 글로 작성 - 말투: 친근하고 이해하기 쉽게 각 에이전트를 별도 파일로 만들고, 팀장이 리서처·라이터를 지휘하는 구조로 설정해줘.
서브 에이전트 폴더 생성 확인
# 현재 폴더 구조 확인 — 에이전트 파일이 생겼는지 확인 ls # 예시 출력 — 아래처럼 나오면 성공! team-lead.md # 팀장 에이전트 researcher.md # 리서처 에이전트 writer.md # 라이터 에이전트 team.json # 팀 설정 파일 # 파일이 없으면 클로드에게 요청 에이전트 파일이 어디 저장됐어? 폴더 구조 보여줘.
STEP 2 — 서브 에이전트를 Teams로 옮기기
💡 왜 Teams로 옮기나요?

STEP 1에서 만든 에이전트들은 탑다운 구조 (팀장 지시 → 팀원 실행)입니다.
이걸 Teams로 등록하면 에이전트끼리 자유롭게 대화하는 바텀업 모드도 쓸 수 있게 됩니다.
같은 에이전트를 두 가지 방식으로 활용하는 것이 핵심입니다.

STEP 2-0 · 만든 에이전트를 Teams에 등록하기
# STEP 1에서 만든 에이전트 3개를 팀으로 등록 방금 만든 팀장·리서처·라이터 에이전트를 "콘텐츠팀"이라는 이름의 팀으로 등록해줘. 팀 구성: - 팀장: 전체 지휘, 결과 취합·검수, 재오더 담당 - 리서처: 정보 수집 및 요약 담당 - 라이터: 콘텐츠 작성 담당 팀 설정 파일도 같이 만들어줘.
💡 팀 등록 후 확인 — ls로 팀 설정 파일이 생성됐는지 확인하세요. 보통 team.json 또는 team-config.md 형태로 만들어집니다.
STEP 3 — Teams 기능으로 에이전트 대화시키기
STEP 3-1 · 에이전트끼리 커피챗하게 만들기
# Teams 모드 — 바텀업 자유 대화 콘텐츠팀 에이전트들이 서로 짧은 커피챗을 나누게 해줘. 주제는 "요즘 AI 트렌드에서 제일 흥미로운 것"으로. 각자 2~3문장씩 3번 주고받으면 돼.
STEP 3-2 · 대화 멈추게 하기
# 자연어로 멈추기 에이전트 대화 지금 멈춰줘. # 또는 터미널 강제 종료 Ctrl + C
💡 Teams 활용 포인트 — 종료 조건을 명확하게 지시하지 않으면 무한 루프에 빠집니다. "3번 주고받으면 종료"처럼 반드시 횟수나 조건을 함께 지정하세요.
STEP 3-3 · 실무 파이프라인 — 팀장 지휘로 보고서 완성
# 탑다운 모드 — 팀장이 전체 지휘 팀장 에이전트에게 아래 작업을 시작하라고 해줘. 주제: "재택근무 도입 효과" 작업 순서: 1. 팀장이 리서처에게 조사 오더 2. 리서처가 핵심 정보 3가지 정리 후 팀장에게 보고 3. 팀장이 검수 → 보완 필요하면 재오더, 통과하면 라이터에게 전달 4. 라이터가 A4 1장 보고서 초안 작성 후 팀장에게 보고 5. 팀장이 최종 검수 → report.md로 저장 완료되면 최종 파일 경로 알려줘.
실습 체크

팀장·리서처·라이터 3개 에이전트를 만들고 Teams에 등록해보세요. 커피챗 시킨 후 중간에 멈추는 것까지 해보고, 마지막으로 팀장 지휘 파이프라인으로 보고서를 완성해보세요!

Notion MCP 연결 실습

2시간 · 개념 20분 + 설치 50분 + 실습 50분
학습 목표
  • Notion API 토큰 발급
  • claude_desktop_config.json 파일 작성 및 저장
  • Claude Desktop 재시작 후 MCP 연결 확인
  • 실습: 대화 내용 → Notion 페이지 자동 생성
STEP 1 — Notion API 토큰 발급
  1. Chrome에서 notion.so/my-integrations 접속 (로그인 필요)
  2. + New integration 클릭
  3. 이름 입력 (예: Claude연동) → 워크스페이스 선택 → Submit
  4. 생성된 Internal Integration Token 복사 (secret_으로 시작)
  5. 연동할 Notion 페이지 → 우측 상단 … → Connections → 만든 통합 추가
⚠️ 토큰은 절대 공유하지 마세요 — 이 토큰으로 내 Notion 전체에 접근할 수 있습니다. 메모장에 임시 저장 후 안전하게 보관하세요.
STEP 2 — Claude CLI에서 Notion 토큰 연결
💡 CLI에서는 이렇게 간단하게

Claude Desktop은 JSON 설정 파일을 따로 만들어야 하지만, Claude CLI(Claude Code)는 토큰을 환경변수로 바로 넘기면 끝입니다. 파일을 따로 만들 필요가 없어요.

Notion 토큰 환경변수로 설정하고 Claude 실행
# 작업 폴더로 이동 cd C:\Users\$env:USERNAME\Desktop\claude-work # Notion 토큰을 환경변수로 설정하면서 Claude 실행 $env:NOTION_TOKEN = "secret_여기에_토큰_붙여넣기" claude # 이렇게 하면 Claude CLI가 Notion 토큰을 바로 인식!
💡 매번 입력하기 번거롭다면 — 작업 폴더에 .env 파일을 만들고 NOTION_TOKEN=secret_...을 저장해두면, 다음부터는 claude만 실행해도 자동으로 불러옵니다.
.env 파일로 저장해두기 (선택)
# .env 파일 생성 New-Item -Name ".env" -ItemType File notepad .env # 메모장에 아래 내용 입력 후 저장 NOTION_TOKEN=secret_여기에_토큰_붙여넣기
STEP 3 — Claude CLI에서 Notion 페이지 생성 실습
회의 내용 → Notion 자동 정리
# Claude CLI 실행 후 아래 입력 아래 회의 내용을 Notion에 새 페이지로 정리해줘. [회의 내용] 오늘 팀 회의에서 3월 신규 프로젝트 일정을 논의했다. 디자인팀은 3/15까지 시안 완성, 개발팀은 3/25까지 1차 개발 완료하기로 했다. 다음 회의는 3/20 오후 2시. [Notion 페이지 형식] - 제목: 2025년 3월 팀 회의록 - 담당자별 할일을 표 형식으로 정리 - 다음 회의 일정 강조 표시
⚠️ Notion 연결 오류 해결법
Notion API error: unauthorized / 401
원인: 토큰이 잘못됐거나 환경변수가 안 잡힘
해결 1: $env:NOTION_TOKEN 값 다시 확인
해결 2: notion.so/my-integrations → 토큰 재발급 후 재설정
object_not_found / 페이지를 찾을 수 없음
해결: Notion 페이지 → 우측 상단 … → Connections → 만든 통합 추가됐는지 확인
토큰 설정했는데 Claude가 Notion을 모른다고 함
해결: PowerShell을 닫지 말고 토큰 설정한 같은 창에서 claude 실행. 새 창을 열면 환경변수가 초기화됩니다.
실습 체크

토큰 설정 후 위 프롬프트로 Notion 페이지가 자동 생성되는지 확인해보세요. Notion에 페이지가 만들어졌으면 성공입니다. 7강 Discord 봇 실습에서 이 토큰을 그대로 씁니다.

Claude CLI 채널 기능으로 Discord → Notion 메모 자동화

2시간 · 종합 실습 90분 + 복습 & Q&A 30분
학습 목표
  • Claude CLI의 채널(Channel) 기능 개념 이해
  • 6강에서 연결한 Notion MCP를 Discord와 연결하기
  • Discord 채널에서 메시지 입력 → Notion 자동 저장
  • 코딩 없이 CLI 프롬프트만으로 전체 자동화 구성
💡 Claude CLI 채널 기능이란?

Claude Code(CLI)에서 외부 서비스(Discord 등)를 직접 채널로 연결해 메시지를 감지하고 처리하는 기능입니다.

코드를 짜지 않아도 Claude CLI가 Discord 메시지를 받아서, 6강에서 이미 연결한 Notion MCP를 통해 자동으로 저장합니다.

핵심: 6강의 Notion MCP + 7강의 Discord 채널 연결 = 완전 자동화

6강에서 한 것

Notion MCP 연결 → Claude CLI가 Notion 페이지 직접 생성 가능

7강에서 추가할 것

Discord 채널 연결 → CLI가 메시지 감지 후 Notion으로 자동 전달

완성 후 흐름

Discord 채팅 입력 → Claude CLI 감지 → Notion 자동 저장

STEP 1 — Discord 봇 생성 & 토큰 발급
  1. Chrome에서 discord.com/developers/applications 접속
  2. New Application → 이름 입력 (예: NotionMemo) → Create
  3. 왼쪽 메뉴 Bot → Add Bot
  4. Reset Token → 토큰 복사해서 메모장 보관
  5. Message Content Intent 켜기 → Save Changes
  6. OAuth2 → URL Generator → bot + Send Messages · Read Message History 체크 → 생성된 URL로 내 Discord 서버에 봇 초대
⚠️ 토큰 절대 공유 금지 — Discord 봇 토큰은 메모장에만 보관하세요.
STEP 1-1 — CLI에 Discord 플러그인 설치 & 봇 페어링
discord-notion-bot 폴더 생성 & 플러그인 설치
# 봇 프로젝트 폴더 생성 및 이동 cd C:\Users\$env:USERNAME\Desktop\claude-work mkdir discord-notion-bot cd discord-notion-bot # package.json 초기화 npm init -y # Discord 플러그인 설치 npm install discord.js @notionhq/client dotenv
설치 확인 — 아래처럼 나오면 성공
